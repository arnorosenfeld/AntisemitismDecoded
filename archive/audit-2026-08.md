# Audit and repair — August 2026

A full review of the engine, the authored content, and the editor, followed by
repairs. This note exists so a future editor understands *why* things are the
way they are, and which mistakes are easy to repeat.

Branch: `fix/audit-2026-08` · Commits: `70983a8`, `71dd3ce`, `59c818a`, `8bd01e6`

## The one thing to take away

**A wrong ID in this codebase does not throw an error. It does nothing, quietly.**

A trait lock naming a trait that doesn't exist simply never opens. A mission
alignment naming a deleted mission simply never awards a star. A conversation
triggered by a missing scenario simply never fires. Nothing appears in the
console; the game just quietly has less content than you think.

That is how **140 dangling references** accumulated without anyone noticing —
including 19 choices that no player, on any playthrough, could ever reach.

There is now a **"Check for broken references"** button on the editor's
Dashboard. Run it before you publish, especially after deleting or renaming
anything.

## What was wrong, and what it teaches

### 1. Renaming things is the main hazard

Every content bug found traced back to something being renamed or deleted while
the references to it were left behind.

- **Traits.** Content gated choices on `master_fundraiser`, `grassroots_organizer`,
  `jewish_scholar`, `press_option`, `political_option`, `halachic_option`,
  `coalition_option`, `major_gift_option`. None are trait IDs. They are trait
  *display names* in snake_case — because the editor's dropdown offered them
  that way (see §3). The real IDs are `fundraiser`, `organizer`, `scholar`,
  `media_savvy`, `political_operator`, `community_insider`, `outsider_voice`.
  19 choices were unreachable.

- **Missions.** 121 alignment tags pointed at `social_justice`, `community_hub`
  and `jewish_identity`, three missions that had been removed. Those choices
  silently awarded no mission star and displayed no ✓/✗ badge. Stripped, after
  measuring that only 18 of 308 choices became newly neutral and every
  surviving mission kept solid coverage.

- **Characters.** The advisor `program_dir` was renamed to Adam Kaufman, but his
  own conversation (`conv_advisor_avi_burnout`) still called him "Avi" in six
  places — the player said *"Avi, I hear you"* to a portrait labelled Adam
  Kaufman.

**If you rename or delete a trait, mission, advisor, coalition, scenario or
sub-mission, run the validator immediately.** Also grep the conversations for
the old character name; dialogue text is not something an ID check can catch.

### 2. Documented mechanics that were never implemented

The help panel told players *"Every round your stats naturally decay… you have
to keep running to stay in place. There are no perfect choices."* No such code
existed. Only Jewish Security drifted; trust, morale and donors never decayed.
Without it there was no pressure to keep acting and banking a round was free.

Now implemented as `applyStatDecay()`, controlled by **`config.statDecayPerRound`**
(currently `1`, set `0` to disable). Two details worth knowing if you tune it:

- Trust decays through its **underlying segment approvals**, not the composite.
  Decaying `G.stats.trust` directly would be recalculated away by
  `computeCompositeTrust()`.
- It runs **after** `recordStatSnapshot()`, so decay appears in the round
  summary as part of that round's movement instead of being invisible.

Similarly, three fields were editable in the editor, saved to the data, and
never read by the engine — so authors were configuring things that did nothing:

| Field | Now does |
|---|---|
| `politicalRange` (min/max) | Gates a scenario by the player's position |
| `groupId` | Only one variant of an event can appear per game |
| `config.tiltPositions` | Drives org starting positions |

`tiltPositions` is the cautionary one: `getOrgStartingPosition()` hardcoded
left 25 / center 50 / right 75, which *matched the config defaults*, so the
feature looked functional while editing it changed nothing.

### 3. The editor was manufacturing the broken content

The "Requires Trait" dropdown was a hardcoded list that had fallen out of sync
with the actual traits. Every choice authored through it got an unusable value.

It now generates from `GD.characterTraits`. An unrecognized value shows as
**"⚠ Unknown trait — no player can pick this"** and stays selected, rather than
disappearing on save.

> **General rule: never hardcode a list in the editor that mirrors game data.**
> Generate it. A hardcoded list is a rename away from silently producing broken
> content.

Related trap: `saveScenario` drops mission alignments it doesn't recognize. So
re-saving a scenario that referenced a deleted mission silently erased that
data. The validator now surfaces these before a save destroys the evidence.

### 4. Three ways the editor could destroy your work

All three are now guarded, but understand the model:

- **Auto-pull on login** only warned if you had *never* pulled. The ordinary
  cycle — pull, edit, close without publishing, reopen — sailed past the check
  and overwrote local edits. There is now a `gd_clean` baseline recorded at
  every pull and publish; any drift from it prompts.
- **Publish had no conflict detection.** It fetched the file and spliced your
  copy in, so a colleague's published edits (or a direct commit) were
  overwritten silently. Publish now compares the remote data against your
  baseline first.
- **Publish only flushed *some* panels.** Config, Page Text, Politics, Momentum,
  Segments and Tooltips auto-save; per-item forms (scenarios, inbox, breaking
  news, advisors, coalitions, conversations) only reach `GD` when you click that
  form's own **Save**. Publish now warns if forms are open.

**Habit worth keeping: click Save on the form, then Publish.**

### 5. `Reset to Defaults` is not "get the latest"

`DEFAULT_GD` is a snapshot baked into `editor.html` at build time. It had
drifted so far that resetting would have reintroduced all 140 dangling
references. It has been re-synced, and the confirm dialog now says so.

**This blob does not update itself.** When `index.html`'s `GAME_DATA` changes
materially, re-sync it or the two drift apart again. To get current content,
use **Pull from GitHub**, not Reset.

## Engine bugs fixed (for context when reading the code)

| Bug | Why it happened |
|---|---|
| Coalition offers ignored round gating | Code read `offerRound`; data authors `offeredByRound`. The function that read the correct field had been superseded and was never called. |
| Round summary showed wrong deltas | Diffed against the start of the *previous* round. Round 1 looked right, hiding it. |
| A reload lost the whole round | Saved only at round start. Now saves at every committed state. |
| Email addresses vanished | `Name <addr@org>` interpolated unescaped, so the browser ate the address as a tag. |
| Inbox timers straddled rounds | Per-action by design, but labelled "rounds" and never expired at a boundary. |
| Coalitions broke unfairly | A strike fired for *any* choice made while a stat sat below the line — including the choice that fixed it. Now requires the choice to have moved the stat, plus one round-end sweep. |
| "Fired at 20" vs. actual 15 | Copy hardcoded a number instead of reading `failureBarThreshold`. |

Also: locked choices rendered `disabledonclick=` (missing space, so not actually
disabled); the year-end Gelt delta baselined on the running *peak* so it could
never be positive; the score breakdown omitted the budget modifier so it visibly
didn't add up; End Round stayed clickable during conversations; one-time
breaking news re-fired after a reload; `restartSameCharacter` leaked the
promoted desk and used call topics into the next run.

## Conventions to preserve

**Editing `GAME_DATA` programmatically.** Parse the block between the
`/* GAME_DATA_START */` / `/* GAME_DATA_END */` markers as JSON, mutate the
object, and reserialize. Never string-splice or regex-replace inside it — the
content contains em dashes, curly quotes and emoji, and a careless replace
corrupts the file in ways that are hard to spot.

**Thresholds and tunables belong in `config`,** and player-facing copy should
interpolate them (`{threshold}`) rather than restating the number. The
"fired at 20" bug existed because the number was written into prose.

**Fallback constants should agree.** `totalRounds` had fallbacks of 4, 5 and 6
at different call sites; `missionStarPoints` had 1 and 5. They are normalized,
but the trap is live: an inconsistent fallback only bites once someone removes
the config key.

**Portrait paths are asset directories, not names.** `art/advisors/avi_rosen`
serves Andy Rose and `art/advisors/rachel_steinberg` serves Laura Gelman. Don't
"fix" these to match character names without renaming the actual folders.

## Verification performed

Multiple complete 5-round playthroughs via the normal setup path, ending in both
a mid-year failure and a promotion; each bug reproduced before the fix and
re-checked after; syntax checks on both files after every batch of edits; zero
console errors. The reference validator reports clean against both `index.html`
and the editor's embedded defaults.

## Known remaining item

Game password, editor password and the GitHub token are all client-side and
readable by anyone with the file. Fine as a playtest gate. The token is the one
that matters — use a fine-grained PAT scoped to this repository's contents only.
